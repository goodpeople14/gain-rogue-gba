# Gain Rogue GBA 아키텍처 지도

이 문서는 현재 구조를 빠르게 이해하기 위한 얇은 지도다. 세부 구현의 1차 근거는 항상 코드이며, 이 문서는 코드와 다를 경우 수정 대상이다.

## 현재 책임 지도

```text
입력
  ↓
PlayerController
  ↓
Character / 구체 캐릭터
  ↓
GameScene ─────────────── 시스템 조정
  │
  ├─ 이동 / Pushbox 기반 물리 충돌
  ├─ 공격 / Hitbox ↔ Hurtbox
  └─ 피격 시각 효과 / HitEffectManager
```

- `PlayerController`: 입력을 이동·공격 의도로 변환한다.
- `Character`: 공통 위치, 방향, 이동속도, 스프라이트와 충돌 몸체를 관리한다.
- 구체 캐릭터: 캐릭터 고유 행동과 공격을 관리한다.
- `GameScene`: 시스템 간 흐름을 조정한다.
- `Hitbox`: 공격을 전달하는 공간 영역이다.
- `Hurtbox`: 공격을 받을 수 있는 공간 영역이다.
- `Pushbox`: 물리적 겹침을 막는 공간 영역이다.
- `HitEffectManager`: 실제 적중 위치의 공통 피격 이펙트를 관리한다.

전투 상세 규칙은 `docs/combat-rules.md`를 따른다.

## 다음 구조 과제

아래는 아직 구현 완료 구조가 아니라 다음 설계·개발에서 검증할 대상이다.

### 1. 충돌 구조 고도화

현재의 `Hitbox` / `Hurtbox` / `Pushbox` 구분은 유지한다. 다음 단계에서는 객체 수가 늘고 맵 충돌이 추가되어도 역할이 섞이지 않도록 충돌 책임을 더 명확히 한다.

검토 대상:

- 캐릭터 대 캐릭터 Pushbox 충돌
- 캐릭터 대 맵/타일 이동 충돌
- 공격 Hitbox 대 Hurtbox 판정
- 충돌 후보 탐색과 실제 판정 책임의 분리 여부
- 플레이어와 적이 공유할 수 있는 최소 공통 피해 처리 인터페이스

### 2. 타일별 상태 레이어

맵의 각 타일이 이동과 지형 의미를 가질 수 있도록 별도 타일 상태 구조를 설계한다.

초기 후보 의미:

- 이동 가능 타일
- 이동 불가 타일
- 필요 시 이후 추가할 지형 속성

중요 원칙:

- 타일 상태는 맵/공간의 성질을 표현한다.
- 무적, 슈퍼아머, 피격 불가 같은 캐릭터 상태는 타일 상태나 충돌 영역 종류로 표현하지 않는다.
- 실제 타일 상태 종류와 저장 방식은 기존 맵 구조 및 GBA 메모리 비용을 확인한 뒤 최소 범위로 결정한다.

## 문서 신뢰 규칙

- 코드: 현재 동작의 1차 근거
- 이 문서: 현재 구조를 설명하는 2차 근거
- `docs/decisions/`: 중요한 결정과 이유
- `docs/journal/`: 생각의 변화, 실패, 발견과 배운 점

문서와 코드가 충돌하면 문서를 그대로 사실로 간주하지 말고 실제 코드를 확인한다.
