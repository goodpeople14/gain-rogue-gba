# 전투 규칙

이 문서는 현재 `main`에 구현된 전투 구조만 기록한다. 아직 구현되지 않은 무적, 슈퍼아머 또는 일반화된 적 시스템을 규정하지 않는다.

## 책임

- `Character`는 공통 위치, 방향, 이동속도, 스프라이트와 `CollisionBody`를 관리한다.
- 구체 캐릭터 클래스는 캐릭터 고유 전투 행동을 소유한다. 현재 `Swordsman`이 `SwordsmanAttack`을 소유한다.
- `PlayerController`는 키 입력을 이동 및 공격 의도로 변환하며 피해를 적용하지 않는다.
- `GameScene`은 입력, 이동 해결, 업데이트와 시스템 간 상호작용을 조정한다.
- `TrainingDummyManager`는 허수아비 슬롯, 생성, 활성 객체 순회와 검사 공격 해결을 담당한다.
- `SwordsmanAttack`은 공격 재사용 시간, 근접 히트박스 활성화와 참격 이펙트 재생을 관리한다.
- `MeleeHitbox`는 공격 활성 시간, 공간 충돌 검사, 공격력과 공격별 피격 기록을 관리한다.
- `HitEffectManager`는 공통 피격 이펙트의 고정 슬롯, 생성, 프레임 진행과 정리를 관리한다.

새 기능이 이 책임에 맞지 않아 구조 변경이 필요하면 기능 구현과 분리해 먼저 제안한다.

## 충돌 영역의 의미

- `Hitbox`: 대상과 접촉해 공격을 전달하는 영역
- `Hurtbox`: 공격을 받을 수 있는 영역
- `Pushbox`: 물리적 겹침을 막고 이동을 해결하는 영역

충돌 영역 종류로 캐릭터 상태를 표현하지 않는다. 충돌 영역은 공간 관계를, 캐릭터와 전투 상태는 별도 상태값을 표현한다.

## 피해 적용

```text
공격 요청
→ SwordsmanAttack 활성화
→ 프레임 기반 MeleeHitbox 갱신
→ Hitbox와 Hurtbox 접촉 검사
→ 공격별 대상 ID 확인
→ 피해량과 적중 위치 반환
→ 대상이 피해 적용
→ HitEffectManager가 적중 위치에 공통 피격 이펙트 생성
```

`AttackHitRegistry`는 한 번 활성화된 공격이 같은 대상에게 중복 피해를 주지 않도록 한다. 근접 공격 시간이나 히트박스를 변경해도 이 성질을 유지한다.

프레임별 히트박스 좌표는 공격 프레임 데이터에 둔다. 시각 이펙트 프레임과 게임 판정 프레임은 같은 상태로 취급하지 않는다.

참격 이펙트는 공격의 방향과 진행을 표현하고, 공통 피격 이펙트는 실제 공격이 적중한 위치를 표현한다. 시각 이펙트만으로 적중 여부를 결정하지 않는다.

## 고정 용량

현재 전투 프로토타입은 다음 고정 용량을 사용한다.

- 허수아비 최대 개수와 고정 슬롯
- 고정 용량 공격 피격 기록
- 공격 프레임당 최대 히트박스 수
- 공통 피격 이펙트의 고정 슬롯

한도를 늘릴 때는 Butano 컨테이너, 메모리 사용량, 반복문과 대상 ID 처리를 함께 확인한다.

## 아직 확정되지 않은 구조

현재 `main`에는 다음 공통 구조가 없다.

- 무적
- 슈퍼아머
- 플레이어와 적이 공유하는 피해 인터페이스
- 일반화된 적 관리자

문서를 맞추기 위해 이 구조를 임의로 만들지 않는다. 기능에 필요해질 때 기존 책임을 기준으로 최소 범위를 설계하고, 구현과 검증 후 이 문서를 갱신한다.

## 검증

전투 변경 시 해당되는 항목을 확인한다.

- 공격 시작, 활성 및 재사용 시간
- 방향에 맞는 히트박스 선택
- 의도한 경계에서의 접촉 판정
- 비활성 프레임에서 피해가 발생하지 않는지
- 한 공격이 같은 대상에게 중복 피해를 주지 않는지
- `Pushbox`가 `Hurtbox`와 혼동되지 않고 이동을 막는지
- 체력이 0이 되었을 때 대상이 비활성화되는지
- 참격 이펙트와 판정 방향이 일치하는지
- 피격 이펙트가 실제 적중 위치에 생성되고 정해진 프레임 뒤 정리되는지
- `make -j2` 빌드
- mGBA 실제 동작

충돌 및 검사 공격 데이터의 기존 컴파일 타임 검증은 계속 통과해야 한다.
