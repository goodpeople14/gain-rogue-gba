# Decision 001: 공간 정보와 게임 상태의 책임을 분리한다

- 상태: Accepted
- 날짜: 2026-08-10

## 배경

충돌과 히트박스 구조를 확장하면서 무적, 슈퍼아머 같은 상태를 히트맵/공간 타입으로 함께 표현하면 계산이 단순해질 수 있다는 아이디어를 검토했다.

동시에 맵 개발을 앞두고 타일마다 이동 가능 여부나 지형 성질을 표현할 필요가 생겼다.

## 결정

공간 구조는 위치, 주변 후보, 타일/지형의 공간적 성질을 표현한다.

캐릭터의 무적, 슈퍼아머, 피격 가능 여부 같은 게임 상태는 캐릭터 또는 해당 게임 로직의 별도 상태로 관리한다.

`Hitbox`, `Hurtbox`, `Pushbox` 역시 공간 관계를 표현하는 현재 의미를 유지하며 캐릭터 상태를 대신 표현하지 않는다.

향후 공간 후보 탐색을 담당하는 공통 구조를 도입하더라도 해당 구조는 게임 상태를 직접 변경하지 않는 방향을 우선한다. Effect/Trigger와 같은 의미 해석 계층이 필요한지는 실제 기능 구현 시 기존 코드를 조사한 뒤 결정한다.

## 이유

- 공간 정보와 게임 규칙의 책임이 섞이는 것을 막는다.
- 캐릭터 상태 전환이 충돌 데이터 표현에 종속되는 것을 피한다.
- 맵 타일 상태를 도입할 때 지형 속성과 캐릭터 상태를 명확히 구분할 수 있다.
- 충돌 후보 탐색과 실제 게임 효과 적용을 독립적으로 발전시킬 여지를 남긴다.

## 검토했지만 채택하지 않은 방식

### 히트맵/공간 타입으로 무적·슈퍼아머까지 표현

초기에는 같은 판정 구조에서 처리할 수 있어 단순해 보였다.

하지만 공간의 성질과 캐릭터의 일시적인 전투 상태가 하나의 타입 체계에 섞이고, 공격·이동·상태 전환이 공간 시스템에 과도하게 의존할 가능성이 있어 채택하지 않았다.

## 후속 과제

- 현재 충돌/이동 코드에서 객체 후보 탐색 책임이 어디에 있는지 확인한다.
- 캐릭터 대 캐릭터, 캐릭터 대 타일, 공격 대 피격 판정의 공통점과 차이를 조사한다.
- 타일 상태는 이동 가능/불가부터 최소 범위로 시작하고 실제 필요가 확인될 때 확장한다.
- Effect/Trigger 계층은 이름이나 클래스를 먼저 만들지 말고 실제 책임이 생길 때 도입한다.
