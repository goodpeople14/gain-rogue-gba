# GBA 개발 핵심

이 문서는 Gain Rogue GBA 프로젝트를 진행할 때 우선 이해해야 할 핵심만 정리합니다.

## 핵심 10가지

1. GBA 화면 해상도는 `240×160`입니다.
2. 게임은 보통 초당 약 60프레임으로 갱신됩니다.
3. Butano에서는 `bn::core::update()`를 기준으로 한 프레임씩 진행됩니다.
4. 십자키로 직접 입력할 수 있는 방향은 최대 8방향입니다.
5. 캐릭터는 보통 전체 화면 비트맵이 아니라 스프라이트로 표시합니다.
6. 배경은 작은 타일을 조합하는 방식이 메모리 사용에 유리합니다.
7. 스프라이트와 배경은 사용할 수 있는 타일, 팔레트, 개수에 제한이 있습니다.
8. 실수 연산보다 Butano의 `bn::fixed` 같은 고정소수점을 사용합니다.
9. 입력의 `pressed`, `held`, `released`는 서로 다른 상태입니다.
10. 동적 메모리보다 고정 크기 배열과 미리 정한 최대 개수를 사용하는 편이 안전합니다.

## 현재 설계에 적용한 예

허수아비 시스템은 위 특성을 고려해 다음과 같이 설계합니다.

- 최대 3개
- 고정 슬롯 사용
- 60프레임마다 1개 생성
- 동적 메모리 사용 금지

## 거너 8방향 스프라이트

![거너 8방향 스프라이트 시트](assets/gunner-8dir-sheet.png)

실제 게임용 시트의 크기는 `128×16`입니다.

- 프레임 크기: `16×16`
- 방향 수: 8
- 계산: `16×16 프레임 × 8방향 = 128×16`
- 프레임 순서: 아래, 왼쪽 아래, 왼쪽, 왼쪽 위, 위, 오른쪽 위, 오른쪽, 오른쪽 아래

큰 확대 이미지는 픽셀 작업을 확인하기 위한 참고 이미지이며, 게임에서는 위의 작은 시트를 사용합니다.
